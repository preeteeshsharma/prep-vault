## Day 1 — Domain-informed machine coding (logistics/dispatch)

### Machine Coding: Delivery Order Assignment System
- **Pattern / goal:** Assign orders to delivery agents with constraints (capacity, time windows, zones). Test extensibility, concurrency, and SOLID design at SDE3 level.
- **Approach:**
  - **Step 1 (~5 min):** Read problem statement; identify entities (Order, DeliveryAgent, Zone, TimeWindow); list key operations (assignOrder, updateAgentCapacity, reassign on constraint violation).
  - **Step 2 (~10 min):** Sketch class hierarchy on paper — use Strategy pattern for assignment algorithms (greedy by distance, by load, by zone affinity); use Observer for state changes; sealed interfaces to prevent illegal states.

  - **Step 4 (~15 min):** Add edge cases: reject order if no agent available, handle concurrent assignment requests (thread-safe queue or lock), handle agent going offline mid-route, time window violations. Trace a realistic scenario (order arrives, 2 agents available, one closer but full, one farther but free).

- **Approach:**
  - **Step 1 (~5 min):** Clarify scope — single-machine or distributed? Per-user or per-endpoint? Responses: assume single-machine, per-user, token bucket. List entities: User, RateLimitBucket, RateLimitPolicy.
  - **Step 2 (~10 min):** Design: use a Strategy pattern for bucket types (token bucket, sliding window, leaky bucket). Data model: userId → BucketState (tokensAvailable, lastRefillTime, capacity, refillRate).
  - **Step 3 (~40 min):** Implement token bucket: allow() checks tokens, refills based on elapsed time, rejects if insufficient. Use a ConcurrentHashMap for thread-safety. Happy path: 10 requests/sec, all pass; 11th rejected. Implement refill logic correctly.

### Machine Coding: Scheduling Engine (Delivery Time Slots & Optimization)
- **Pattern / goal:** Schedule deliveries into time slots (e.g., 9–11am, 11am–1pm) across multiple zones. Balance load, respect constraints, and design for easy extension (new zone types, new slot policies).
- **Approach:**
  - **Step 1 (~5 min):** Identify entities: DeliveryOrder (id, destination, deadline, priority), TimeSlot (startTime, endTime, capacity, zone), Scheduler (assign order to slot respecting constraints). List operations: addOrder, getSlotForOrder, listAvailableSlots.
  - **Step 2 (~10 min):** Design: use Strategy for slot selection (first-fit, best-fit, round-robin). Use Factory for creating time slots by zone or by SLA tier. Immutable TimeSlot VO; mutable Scheduler state. SOLID: depend on abstract Slot Strategy, not concrete slot logic.
  - **Step 3 (~40 min):** Implement: TimeSlot tracks remaining capacity; Scheduler maintains a map of zones → available slots. addOrder() calls strategy.selectSlot(order, availableSlots); if found, decrement slot capacity; if not found, throw NoAvailableSlotException. Get basic flow working: create 2 zones, add 3 slots per zone, assign 4 orders, verify capacity checks and rejection.
  - **Step 4 (~15 min):** Edge cases: slot fills up mid-assignment (queue order or reject), order arrives after all slots closed (dynamic slot creation?), zone not supported (exception), concurrent assignments to same slot (lock or CAS), change SLA policy mid-day (add new slot strategy without touching existing code — show it's extensible).
- **Time:** 90 min

## Interview Strategy Notes

**For Locus SDE3 machine coding**, focus on:

1. **Extensibility over perfection** — show that adding a new vehicle type, new rate-limit strategy, or new assignment algorithm requires changing only 1–2 classes. SDE3 bar expects design that scales to 5+ new requirements mid-round.

2. **Concurrency & thread-safety** — Locus's platform runs at scale. Use `ConcurrentHashMap`, appropriate locks, or atomic variables. Don't just say "add synchronization" — actually implement it.

3. **SOLID principles** — especially **Open/Closed** (open for extension, closed for modification). Use interfaces and Strategy/State patterns liberally.

4. **Domain knowledge** — dispatch, routing, and logistics constraints are Locus's core. Show you understand capacity, time windows, zone affinity, and SLAs.

5. **Happy path first** — get a full end-to-end scenario working (order in → assignment → confirmation) before polishing edge cases. Working code beats beautiful design.
