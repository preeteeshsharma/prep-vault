### Round Structure & Format



The "Coding Challenges" block runs **60–90 minutes**, video or in-person.

 There are actually **two distinct coding sub-challenges** that Fivetran uses:

- 

**C1 — Problem Solving:** A fairly standard coding question designed to determine a base level of problem-solving ability in the software language of your choice.


- 

**C2 — Coding Structure & Data Processing:** A more focused coding problem evaluating your ability to interact with a codebase, think about code structurally, and perform basic data manipulation work — given as part of the on-site, in Java (though the interviewer is instructed to assist with language difficulties, so Python engineers can manage with basic Java familiarity).





The typical flow for senior roles is: recruiter call → hiring manager call → 60-minute tech round, followed by a 2-part on-site that includes a second Java-specific technical round and a design round.

### Preparation Tips (from Candidates)

- 

The technical interview process consists of several parts: discussing, estimation (Big O notation), improving or simplifying, coding, checking, and detailed discussion about all pros and cons of your decision.

 Be ready to justify every choice.
- 

Be prepared to explain your thought process and approach during live coding sessions, as interviewers appreciate candidates who can articulate their reasoning and problem-solving strategies.


- 

In the first technical assessment, be ready to write code that gives 100% output with all test cases passing.


- 

One piece of advice for the codebase round: don't waste time understanding their entire code — start by solving the required logic and then look only for what you want in the existing codebase.


- 

You're encouraged to ask questions about the question and about the merits of different options. Does your interviewer have a unique perspective on how to tackle the problem? This interview works best for both participants if it's a conversation.


- 

For senior roles, technologies such as Docker and Kubernetes are also important (beyond DSA).
