### Round Format & Structure



Fivetran uses **two distinct coding challenges** (C1 and C2) in their process. C1 ("Problem Solving") is a fairly standard coding question designed to determine a baseline problem-solving ability in a language of your choice, currently administered on HackerRank.





C2 ("Coding Structure and Data Processing") is a more focused problem given during the virtual onsite, designed to evaluate how you interact with a codebase, think structurally, and perform data manipulation. It is given in Java, though interviewers are instructed to assist with minor language issues (i.e., a Python engineer should still be able to pass).



For the **Senior SWE loop specifically**: 

the process is: 1 phone screen with a LeetCode-medium, then a loop with 1 system design round, 1 coding round where they ask you to add code to an existing codebase, 1 behavioral round, and a manager round. This was confirmed for the Senior Software Engineer level.





One candidate reported that the technical interview process consisted of several parts: discussing, estimation (Big O notation), improving or simplifying, coding, checking, and detailed discussion about all pros and cons of the decision.

### Themes & Patterns

- 

Fivetran interviews typically emphasize **Arrays and Strings**, with a difficulty breakdown of roughly 61% Medium, 23% Easy, and 16% Hard problems across all known questions.


- 

Technical rounds include one DSA question of moderate difficulty (DP, Graph, etc.) combined with core CS questions (DBMS, OOP, etc.).


- **Two coding challenges**: The OA/phone screen problem leans easy-to-medium (pass all test cases on HackerRank). The onsite "C2" coding round involves modifying an existing codebase rather than solving from scratch.
- 

For the Senior SWE specifically: the phone screen features a LeetCode-medium, followed by an onsite loop that includes a coding round where you are asked to add code to an existing codebase.


- Topics confirmed across multiple sources: **Heaps, Graphs, DP (LIS), Greedy (Gas Station variant), Arrays, Hash Maps, Strings, Binary Search**.
- 

The live technical coding process involves: discussion, complexity estimation (Big O), improving/simplifying, coding, checking, and detailed discussion of trade-offs.

### Preparation Tips (from candidates)

- 

Practice LeetCode medium-level problems, and be prepared to explain your thought process and approach during live coding sessions — interviewers appreciate candidates who can articulate their reasoning and problem-solving strategies.


- 

You are encouraged to ask questions about the question and the merits of different options. The interview works best when it's a conversation — ask if your interviewer has a unique perspective on tackling the problem.


- 

At least one candidate noted that interviewers may NOT stop you from going down the wrong path — don't assume you'll get a subtle hint. Walk through your reasoning aloud before diving in.


- 

Code must be **executable** — Fivetran's HackerRank sessions require your solution to actually pass test cases, not just be pseudo-code or directionally correct.


- 

For senior roles specifically, technologies such as Docker and Kubernetes are also relevant (expect CS depth questions alongside DSA).
