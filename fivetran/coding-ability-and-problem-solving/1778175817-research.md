### Round Format & Structure (OFFICIAL — from Fivetran prep guide sent to candidate)

**Round 1 — Coding:**
- Part A: DSA (medium to complex, LeetCode/HackerRank)
- Part B: Performance Engineering — given a Fivetran codebase + Flame Graph (CPU profiling), identify bottlenecks, propose optimizations without changing business logic. Prep: time/space complexity, reading unfamiliar code, profiling graphs, caching/efficient data structures.

**Round 2 — Coding (one of four scenarios):**
- Scenario A: JDBC/Schema — connect to data source, retrieve schema, extract data to Java objects, ingest to internal API
- Scenario B: Caching — CDN challenges, LRU/LFU/FIFO strategies
- Scenario C: Codebase Implementation — implement incomplete functions, make unit tests pass. Debug with breakpoints, not print statements. Design patterns + LLD.
- Scenario D: DSA — Graphs/Queue

**Round 3:** System Design (LLD + HLD)
**Round 4:** Hiring Manager

**Key notes:** Java CPU Profiling + Regex mentioned explicitly. Set up local IDE with Maven. Communicate and clarify proactively.

### Round Format & Structure (community research)



Fivetran uses two distinct coding challenges. **C1 — Problem Solving** is a fairly standard coding question designed to determine a base level of problem-solving ability in the software language of your choice, conducted via HackerRank.





**C2 — Coding Structure and Data Processing** is a more focused coding problem designed to evaluate your ability to interact with a codebase, think about code structurally, and perform basic data manipulation work. It is given as part of the on-site interview, primarily in Java — though the interviewer is instructed to assist with minor language difficulties.



For the live coding interview (C2 / onsite), 

you're encouraged to ask questions about the problem and about the merits of different options. The interview works best for both participants if it's a conversation.





The technical interview round lasts an hour and is typically divided into two parts, both focused on data structures and algorithms.

### Frequently Mentioned Topics (Across Multiple Sources)



Fivetran interviews typically emphasize **Arrays and Strings**. The difficulty breakdown across confirmed problems skews heavily toward Medium, with some Hard problems reported.





The technical round typically includes one DSA question plus CS core questions. The difficulty of DSA questions is described as moderate — covering DP, Graphs, etc.





In at least one account (2021, Russia), the technical interview process consisted of: discussing, estimating (Big O notation), improving or simplifying, coding, checking, and a detailed discussion of all cons and pros of the decision.

### What the Round Is Optimizing For



Interviewers appreciate candidates who can **articulate their reasoning and problem-solving strategies** — be prepared to explain your thought process and approach during live coding sessions.





In each interview, you are expected to have a **two-way conversation** with the interviewer — asking questions is encouraged.





The onsite coding round is one of four components (alongside system design, behavioral, and HM). Interviewers are noted to be quite nice, knowledgeable, and more willing to have a conversation than at other companies.





For a Senior SWE specifically: "1 phone screen with a leetcode medium. Then loop with 1 system design, 1 coding where they ask you to add code to an existing codebase, 1 behavioral round and then manager round" — confirming the onsite coding is a **codebase interaction** problem (C2), not just a blank-slate algorithm question.

### Preparation Tips (From Candidates)

- 

Ensure you are well-versed in **Java, SQL, and data structures**. Practice coding problems similar to those on LeetCode, particularly focusing on medium-level questions.


- 

The coding interview tests **data structures and algorithms, similar to LeetCode, of average difficulty**.


- 

One Blind user who received an offer noted: "the interview process has been lengthy, but hasn't been overly challenging compared to industry standards."


- All test cases must pass on HackerRank — 

you are expected to write executable code and check that all test cases pass.

 Partial credit is not guaranteed.
- 

Multiple coding rounds exist, so it's not a single-knockout format

 — a stumble on one problem doesn't necessarily eliminate you.
