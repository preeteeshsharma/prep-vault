4. **Most Common Character Proportion + Bag Jaccard Similarity** — Two-part problem (Round 4, 45 min)
   - ✅ *Confirmed asked* (SDE-2 L4, Jan 2024) — **candidate explicitly said not solving Part 2 cost them the offer**
   - Part 1: Given list of strings, select strings where most common character has smallest proportion. Return characters only present in selected strings.
   - Part 2 (if time allows): Replace proportion with bag Jaccard similarity. Select strings with lowest average Jaccard vs all others. Bag Jaccard uses character counts: intersection=min counts, union=max counts.
   - Example: S1="baa", S2="abb" → intersection="ab" (len=2), union="aabb" (len=4) → J=1/2
   - Source: [LeetCode Discuss — Moveworks SDE-2 L4, Jan 2024](https://leetcode.com/discuss/interview-experience/4520538/Moveworks-SDE-2-L4-Interview/)
   - **Critical note:** Part 2 bag Jaccard differs from set Jaccard — uses min/max of character frequency maps, not set intersection/union

### Themes & Patterns

- 🔁 **Strings + DP are the #1 topic by far.** Word Break II has appeared in multiple independent accounts across 2023–2025. String parsing, subsequences, substring uniqueness, and synonym/sentence generation all point to a strong string-algorithm bias.
- 🧩 **Two problems per DSA round is the norm.** Most interviewers give 2 questions in a 60-minute window. 

Code must run and pass all test cases — partial credit is not sufficient.


- 📈 **Difficulty escalates across rounds.** 

One candidate reported that in their coding rounds, questions were easy, medium, and tough respectively across the three sessions.


- 🔧 **Backend-specialized tracks go deeper.** The core infrastructure / backend team specifically asks about 

thread-safe KV stores and multithreading

, and also includes a document/prefix search problem using tries.
- ⚡ **Optimal solution is required.** 

You need to provide the most optimal solution

 — brute force alone won't pass.
- ⏱️ **Speed matters.** 

One Glassdoor reviewer noted the challenges "are not complex for a senior engineer but might be hit and miss depending on how you feel that day." They don't require complex algorithms but have non-trivial problems — speed of arriving at a reasonable solution is what's being tested.

### Preparation Tips (from candidates)

- 

Review common LeetCode-style problems, particularly those focusing on **recursion, string manipulation, and data processing**.


- 

Even for non-backend roles, the interviews are backend-heavy — brush up on backend skills, system design, and algorithmic challenges to cover all bases.


- Word Break II (LC #140) is effectively a "must-know" — it has appeared across at least 3 separate candidate accounts spanning 2 years.
- For the backend/infra team track, be comfortable with multithreading primitives (mutex, reader-writer locks) and trie-based search.
